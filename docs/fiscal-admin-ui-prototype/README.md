# Farvoo 开票 · UI 交互原型 v2

> **状态：定稿**（**流程、导航、业务用语**；视觉与组件库非最终）  
> **权威：是**（产品 UI 流程与导航以本文 + 静态页为准；工程里程碑见 [`fiscal-dev-plan.zh.md`](../fiscal-dev-plan.zh.md) **M2.6**）  
> **对应实现：** 正式 Admin 以本文为验收参照；用语改版后实现须跟齐（见修订记录）。

## 设计原则（v2）

1. **先建销售聚合，后有发票** — 手工开票：新建开票 → 加商品 → 确认 → 选发票类型 → 签发。
2. **业务语言** — 界面不出现「草稿、LOCAL、API、M3」等开发词；用语见下节 **P0**。
3. **业态分离** — **餐馆 / 商超由 Ops 下发**（[`fiscal-m3-2-operators.zh.md`](../fiscal-m3-2-operators.zh.md) §3.9）；登录 **不**选业态；UI 按 `fiscal_profile` 显隐菜单（餐馆才有「收银账单」）。
4. **流程可见** — 手工开票页顶栏 **四步进度条**：创建开票 → 添加商品 → 确认 → 开票。
5. **工作台双入口同级（P0）** — 见下节。

## 业务用语（P0 定法 · 方案 A）

**按来源命名；动作统一说「开票」。** 禁止再用「订单 / 待开票账单」作侧栏主名（易撞「待开票」语义）。

| 界面用语（唯一） | 含义 | 内部（勿上 UI） | 旧称（仅文档别名） |
|------------------|------|-----------------|-------------------|
| **收银账单** | 收银系统同步进来、待开 FT 的桌账 | `bill_sync_drafts` / `/local/v1/bill-drafts` | 待开票账单 |
| **手工开票** | 本机手建的销售聚合 → 开票 | 手动 snapshot / 四步流 | 订单 |
| **新建开票** | 工作台 / 列表进入手建路径 | `order-new` 等 | 新建订单 |
| **处理收银账单** | 工作台进入同步账单列表 | `data-nav=bills` | 处理待开票账单 |
| **进入开票** | 从收银账单开始签发（或进四步） | 原「转订单」 | 转订单 |
| 签发发票 / 发票 / 重打 | 不变 | `IssueDocument` / `invoices` / REPRINT | — |

侧栏副文案建议：

| 菜单 | 副文案 |
|------|--------|
| 手工开票 | 本机新建 |
| 收银账单 | 待开票 · 来自收银 |

**依据：** 餐馆主路径是收银同步 → 开票；手工是补路径。名称按来源拆开，避免两个菜单都叫「待开票」。

## 工作台双 CTA（P0 定法）

餐馆工作台同时展示两个大入口时：

| 项 | 定法 |
|----|------|
| 视觉权重 | **同级**：`＋ 新建开票` 与 `处理收银账单` 使用同一套 `.cta-big`（同描边、同卡片感）。**禁止**把「收银账单」做成 `secondary` + 灰边弱化。 |
| 焦点优先 | 存在 **≥1 条** `status=open` 的收银账单时，**「处理收银账单」优先获得焦点**（进入工作台时 `focus()` 落在该按钮；可用角标/数量强化，但不得单独靠弱边框区分主次）。 |
| 无收银账单 | 焦点可落在「新建开票」；「处理收银账单」仍同级可见（点进后为空列表即可）。 |
| 商超 | 仅「新建开票」；无第二入口。 |

**依据：** 同级保证可发现性；有积压时焦点优先收银账单，避免店员误走手工单。

## 手工开票 · 添加商品（P0 定法）

| 项 | 定法 |
|----|------|
| 入口 | 明细 **仅一个**「添加商品」；**禁止**「添加一行」占位空行。 |
| 弹窗 | **唯一商品工作台**：检索（名称/编码）+ 命中选用；无命中可 **新建**（字段与商品页相同：编码/名称/税票名/售价/IVA）。 |
| 新建后 | 写入本地商品库（`POST /local/v1/products`），并 **自动加入本单**。 |
| 商品页 | 「新建/编辑」打开 **同一套字段**（同一 `id` 输入框 / 同一保存函数）；禁止第二套商品表单。 |
| 扫码（业态） | **餐馆：不需要扫码**（点选 / 检索即可）。**商超：需要扫码**，且扫码为加商品主路径；检索 / 新建为兜底。禁止做成「全业态统一扫码」。 |
| 非目标 | 表格内联改名改价的「野行」；无编码临时行 UI；餐馆模式扫码入口。 |

## 收银账单实时提示（P0 定法）

| 项 | 定法 |
|----|------|
| 通道 | Agent **SSE** `GET /local/v1/events`（事件 `bill_drafts_changed`）；**禁止**浏览器空转轮询当主路径。 |
| 侧栏 | 餐馆「收银账单」**角标** = open 条数；商超无此菜单。 |
| 列表 | 在工作台 / 收银账单页时收到事件 → 刷新列表；不强制跳页、不挡填表。 |
| 提示 | open 增加时轻 toast（桌号优先；无桌号用「有新的收银账单」）。 |
| 权威细则 | [`fiscal-bill-draft-workbench.zh.md`](../fiscal-bill-draft-workbench.zh.md) §7.1 |

## 可点路径

| 步骤 | 餐馆 | 商超 |
|------|------|------|
| 登录 | 选开票员 + PIN（**无**业态选择；模式由 Ops） | 同左 |
| 工作台 | 新建开票 + 处理收银账单（**同级 CTA**；有 open 时焦点优先后者） | 新建开票 |
| 手工开票 | 列表 → 继续开票 | 同左 |
| 新建开票 | 桌号 + 商品（检索/点选，**无扫码**）+ 确认 | 收银台 + 商品（**扫码为主**；检索/新建兜底）+ 确认 |
| 开票 | 选 FT + 购方 + 打印 | 同左 |
| 收银账单 | 收银同步 → 进入开票 | （无此菜单） |
| 发票 | 列表（**FT / FS / NC / ND 分 Tab**）→ 详情 → 重打 | 同左 |
