# Farvoo 开票 · UI 交互原型 v2

> **状态：定稿**（**流程、导航、业务用语**；视觉与组件库非最终）  
> **权威：是**（产品 UI 流程与导航以本文 + 静态页为准；工程里程碑见 [`fiscal-dev-plan.zh.md`](../fiscal-dev-plan.zh.md) **M2.6**）  
> **对应实现：** 未接 API；正式 Admin 落地时以本原型为验收参照。

## 设计原则（v2）

1. **先有订单，后有发票** — 手动开票同样：新建订单 → 加商品 → 确认 → 选发票类型 → 签发。
2. **业务语言** — 界面不出现「草稿、LOCAL、API、M3」等开发词；餐馆侧收银同步叫 **「待开票账单」**（内部仍 `bill_sync_drafts`，见 [`fiscal-bill-draft-workbench.zh.md`](../fiscal-bill-draft-workbench.zh.md) §0）。
3. **业态分离** — 登录时选 **餐馆 / 商超**；导航与首页按模式显示不同入口（餐馆才有「待开票账单」）。
4. **流程可见** — 订单/开票页顶栏 **四步进度条**：创建订单 → 添加商品 → 确认订单 → 开票。
5. **工作台双入口同级（P0）** — 见下节。

## 工作台双 CTA（P0 定法）

餐馆工作台同时展示两个大入口时：

| 项 | 定法 |
|----|------|
| 视觉权重 | **同级**：`＋ 新建订单` 与 `处理待开票账单` 使用同一套 `.cta-big`（同描边、同卡片感）。**禁止**把「待开票账单」做成 `secondary` + 灰边弱化。 |
| 焦点优先 | 存在 **≥1 条** `status=open` 的待开票账单时，**「处理待开票账单」优先获得焦点**（进入工作台时 `focus()` 落在该按钮；可用角标/数量强化，但不得单独靠弱边框区分主次）。 |
| 无待开票账单 | 焦点可落在「新建订单」；「处理待开票账单」仍同级可见（点进后为空列表即可）。 |
| 商超 | 仅「新建订单」；无第二入口。 |

**依据：** 餐馆日常主路径是收银同步 → 待开票账单 → 开票；手动新建是补路径。同级保证可发现性；有积压时焦点优先待开票账单，避免店员误走手动单。

## 订单添加商品（P0 定法）

| 项 | 定法 |
|----|------|
| 入口 | 订单明细 **仅一个**「添加商品」；**禁止**「添加一行」占位空行。 |
| 弹窗 | **唯一商品工作台**：检索（名称/编码）+ 命中选用；无命中可 **新建**（字段与商品页相同：编码/名称/税票名/售价/IVA）。 |
| 新建后 | 写入本地商品库（`POST /local/v1/products`），并 **自动加入当前订单**。 |
| 商品页 | 「新建/编辑」打开 **同一套字段**（同一 `id` 输入框 / 同一保存函数）；禁止第二套商品表单。 |
| 非目标 | 订单表格内联改名改价的「野行」；无编码临时行 UI。 |

## 可点路径

| 步骤 | 餐馆 | 商超 |
|------|------|------|
| 登录 | 选餐馆 + PIN | 选商超 + PIN |
| 工作台 | 新建订单 + 待开票账单（**同级 CTA**；有待开票时焦点优先后者） | 新建订单 |
| 订单 | 列表 → 继续开票 | 同左 |
| 新建订单 | 桌号 + 商品 + 确认 | 收银台 + 商品 + 确认 |
| 开票 | 选 FT + 购方 + 打印 | 同左 |
| 待开票账单 | 收银同步 → 转订单 | （无此菜单） |
| 发票 | 列表 → 详情 → 重打 | 同左 |
