# Farvoo 开票 · UI 交互原型 v2

> **状态：定稿**（**流程、导航、业务用语**；视觉与组件库非最终）  
> **权威：是**（产品 UI 流程与导航以本文 + 静态页为准；工程里程碑见 [`fiscal-dev-plan.zh.md`](../fiscal-dev-plan.zh.md) **M2.6**）  
> **对应实现：** 正式 Admin = **`internal/fiscal/bootstrap/ui/admin/`**（bootstrap 嵌入）；本文仅作**流程/导航/用语**验收参照（非 React `web/fiscal-admin`）。用语改版后实现须跟齐（见修订记录）。

## 设计原则（v2）

1. **先建销售聚合，后有发票** — 开票：＋ 开票 → 加商品 → 确认 → 选发票类型 → 签发。
2. **业务语言** — 界面不出现「草稿、LOCAL、API、M3」等开发词；用语见下节 **P0**。
3. **业态分离** — **餐馆 / 商超由 Ops 下发**（[`fiscal-m3-2-operators.zh.md`](../fiscal-m3-2-operators.zh.md) §3.9）；登录 **不**选业态；UI 按 `fiscal_profile` 显隐菜单。**2026-11-03 起：账单同步暂时废弃，餐馆也不再展示「账单」入口**（与商超开票入口一致，仅「＋ 开票」）；后端 `bill_sync_drafts` / 分单视图代码暂留待恢复。
4. **流程可见** — 开票页顶栏 **四步进度条**：创建开票 → 添加商品 → 确认 → 开票。
5. **发票 hub 开票入口（P0 · 临时）** — 现仅「＋ 开票」；原「账单」双 CTA / 侧栏入口见下节「暂停」说明。

## 业务用语（P0 定法 · 方案 A）

**短名；按入口区分。** 禁止再用「订单 / 待开票账单」作侧栏主名。

| 界面用语（唯一） | 含义 | 内部（勿上 UI） | 旧称（仅文档别名） |
|------------------|------|-----------------|-------------------|
| **账单** | 侧栏 + hub 入口（同步待开桌账） | `bill_sync_drafts` / `/local/v1/bill-drafts` | 收银账单；处理收银账单；待开票账单 |
| **开票** | 本机手建四步流；页标题 | 手动 snapshot / `order-new` | 手工开票；新建开票；订单 |
| **＋ 开票** | hub 入口条进入四步流（唯一带「＋」） | `#ctaNewOrder` | ＋ 手工开票；＋ 新建开票 |
| **进入开票** | 从账单开始签发 | 原「转订单」 | 转订单 |
| 签发发票 / 发票 / 重打 | 不变 | `IssueDocument` / `invoices` / REPRINT | — |

**依据（历史）：** 餐馆主路径曾是收银同步 → 开票；本机手建是补路径。  
**临时定法（2026-11-03）：** 账单同步暂停期间，餐馆 / 商超可见开票入口均为「＋ 开票」；侧栏 / hub **不**展示「账单」。用语表中「账单」「进入开票」保留作恢复同步后的权威名，**当前实现不暴露**。

## 发票 hub 开票入口（P0 定法 · 临时暂停账单）

| 项 | 定法（2026-11-03 起） |
|----|------|
| 可见入口 | **仅**「＋ 开票」（`#ctaNewOrder`）。**禁止**侧栏「账单」、hub「账单」CTA、角标、新账单 toast。 |
| 焦点 | 登录后发票 hub 焦点落在「＋ 开票」。 |
| 餐馆 / 商超 | 开票入口一致（仅手建四步流）。 |
| 手工草稿 | **禁止**：无「稍后开票」、无手工待开列表；取消或离开四步流即丢弃本单。 |
| 恢复条件 | 账单同步产品路径重新启用时，再恢复下文「历史双 CTA」口径（侧栏 + hub「账单」同级、有 open 时账单优先焦点）。 |

**历史双 CTA（暂停，勿按现网验收）：** 入口条「账单」（`#ctaPendingBills`）与「＋ 开票」同级；≥1 条 open 时「账单」优先焦点。

## 开票 · 添加商品（P0 定法）

| 项 | 定法 |
|----|------|
| 入口 | 明细 **仅一个**「添加商品」；**禁止**「添加一行」占位空行。 |
| 弹窗 | **唯一商品工作台**：检索（名称/编码）+ 命中选用；无命中可 **新建**（字段与商品页相同：编码/名称/税票名/售价/IVA）。 |
| 新建后 | 写入本地商品库（`POST /local/v1/products`），并 **自动加入本单**。 |
| 商品页 | 「新建/编辑」打开 **同一套字段**（同一 `id` 输入框 / 同一保存函数）；禁止第二套商品表单。 |
| 扫码（业态） | **餐馆：不需要扫码**（点选 / 检索即可）。**商超：需要扫码**，且扫码为加商品主路径；检索 / 新建为兜底。禁止做成「全业态统一扫码」。 |
| 非目标 | 表格内联改名改价的「野行」；无编码临时行 UI；餐馆模式扫码入口。 |

## 账单实时提示（P0 定法 · 临时暂停）

| 项 | 定法（2026-11-03 起） |
|----|------|
| Admin 店员侧 | **静默**：不订阅 SSE 做角标 / toast / hub 刷新（与去掉「账单」入口一致）。 |
| 后端 | `bill_sync_drafts` / ingest / `/local/v1/bill-drafts*` **暂不拆除**，待同步恢复。 |
| 恢复后 | 通道仍为 Agent **SSE** `bill_drafts_changed`；侧栏角标 = open 条数；open 增加时轻 toast。细则见 [`fiscal-bill-draft-workbench.zh.md`](../fiscal-bill-draft-workbench.zh.md) §7.1。 |

**默认页：** 登录后进入「发票」hub（今日统计 + 完整列表）。开票经入口条「＋ 开票」进入四步流；**无**账单菜单、**无**草稿列表、**无**「稍后开票」。

## 可点路径

| 步骤 | 餐馆 | 商超 |
|------|------|------|
| 登录 | 选开票员 + PIN（**无**业态选择；模式由 Ops） | 同左 |
| 发票 hub | 今日统计 + 完整列表；入口条仅「＋ 开票」 | 同左 |
| 开票 | 桌号 + 商品（检索/点选，**无扫码**）+ 确认 | 收银台 + 商品（**扫码为主**；检索/新建兜底）+ 确认 |
| 签发 | 选 FT + 购方 + 打印；取消丢弃回发票 hub | 同左 |
| 账单 | （同步暂停 · 无菜单） | （无此菜单） |
| 发票列表 | **全部 + 本店已注册 ACTIVE 系列的票种 Tab**（`*_series_ok`）→ 详情 → 重打 | 同左 |
