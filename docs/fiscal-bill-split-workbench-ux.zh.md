## 0. 已锁定的 P0

| # | 定法 |
|---|------|
| 壳层 | **专用 main view + 同页开票条**（侧栏保留）；小 Modal 仅用于丢弃/重名等短确认；**否决**小弹窗承载分配器、真全屏、签发窄 Drawer |
| 入口 | `whole_table` 与云端已 `split` **同一套**分单界面；已分单按载荷灌入 |
| **整桌本机分单** | **必须支持。** 云端常为 `whole_table` → 店员在 Agent **代为按菜分单** 再按人开票 |
| 云 | 分单调整与开票 **只落本机**；**不回写** Farvoo / 云端分单 |
| **开票节奏** | **付一张清一张**：顶上人条可多人；**中间 + 开票条永远只服务当前选中的一人**。开成功 → 该人 ✓ → **清空开票条购方** → 自动切下一未开人（有则） |
| **身份** | **跨票无身份约束。** 各张 FT 的购方互相独立；不要求与分单标记名一致，也不要求与上一张票一致 |
| **中间名** | 仅 **分单人名标记**（这份额先记在谁头上）；**不**写入最终发票购方姓名 |
| **开票条** | **唯一购方**：NIF + 名称 → 票面 `Customer`；签发只认这边 |
| **人条** | 顶上 chip：**可点切换**；已开 **✓**；已开 **可点只读**（不可改份额、不可再签） |
| **切人** | 切换 chip **丢掉**当前人未提交的份额/标记改动（不隐式保存） |
| **新人** | **无**独立「添加用餐人」主按钮。在中间 **输入或修改当前人姓名** 即建立/认定分单人（本机新 `scope_id` 或改未开人标记名）；云端已 split **默认加载已知人们**，标记名可改 |
| **提交** | **无**独立「保存分单」主按钮。**签发 = 提交当前人份额 + 开票**；未签发的改动可因切人丢弃 |
| 数量规则 | 与 Restaurant **按菜分单**对齐（有理数：整 + 分子/分母；剩余扣减） |
| 人名标记 | **禁止重名**（大小写不敏感 trim）；阻断并提示 |
| 同步次数 | **同一收银账单只同步一次**；不做「无票再同步 vs 本机编辑」冲突合并 |
| 原桌权威 | 冻结 `source_lines`；本机 `allocation` 另存；分配不得改源行 |
| 清草稿 | **全部未开人已开完，且剩余池为空** 才删草稿 |
| 并发 | allocation **OCC**；见 §5.1 |

## 1. 问题陈述

店员需要：看剩余菜 → 分给当前人 → 开票条填购方 → 签发 → 下一人。  
壳层仍用主区工作台（非小弹窗）；交互按 **单人槽 + 顶上进度人条**，避免「中间同时编多人」和「分单标记名被当成票面购方」。

## 3. 信息架构（P0）

```
侧栏 [收银账单]
  └─ view-bills
       └─ view-bill-split
            ├─ 顶栏：桌号 · 进度 · 返回 / 不再处理未开
            ├─ 人条：chip（可点；已开 ✓；已开可点只读）
            ├─ 左：剩余菜品（可分数量）
            ├─ 中：当前人标记名 + 份额（仅当前选中一人）
            └─ 开票：购方 NIF / 名称 / 签发（仅未开当前人可点）
```

### 3.1 职责

| 区域 | 唯一职责 | 禁止 |
|------|----------|------|
| **人条** | 进度、切换当前人、已开 ✓ | 在人条上改份额/NIF |
| **左 · 剩余池** | 可分数量 | 改价/删菜 |
| **中 · 当前人** | 分单标记名 + 份额 | 当作票面购方；同时编辑第二人 |
| **开票条** | 购方 + 签发 | 分菜逻辑 |

整桌签发：仅当尚未走出按人路径时保留；一旦有按人 FT 或已进入按人分配，隐藏（`scope_mutex`）。

### 3.2 初始灌入

| 同步形态 | 进入时 |
|----------|--------|
| `whole_table` | 左池 = 全部源行；人条空；中间输入姓名即建第一人 |
| `split` | **默认加载** allocation/splits 已知人们到人条；选中 **第一个未开人**；标记名可改 |
| 部分已开 | 已开 ✓ 可点只读；自动选下一未开人；开票条空 |

左池 = 源行 − **全部** allocation 占用（含已开人与未开人已提交份额）。未提交的本地改动只影响当前编辑预览，切人丢弃后回到已提交态。

## 4. 交互细则

### 4.1 数量

整 + 分子/分母；不得超分；规则对齐 Restaurant。

### 4.2 分单标记名 vs 购方名

| 字段 | 用途 |
|------|------|
| 中间「姓名」 | 分单标记；chip 文案；**不**作为发票购方姓名主口径 |
| 开票「购方名称」+ NIF | 票面真正的人 |

允许中间「Marria」、开票「Ali」。跨票购方无约束。

重名（标记名）禁止。云端灌入的人可改标记名（未开时）。

### 4.3 切人

- 点未开 chip → 成为当前人；**丢弃**离开的人未提交改动；**清空开票条**。  
- 点已开 chip → 只读展示其已提交份额/标记；开票条禁用；不可签发。  
- 不在切人时 PUT allocation。

### 4.4 新人 / 无「添加」「保存」主按钮

- 中间输入姓名：若尚无当前未开人槽，则 **创建**新人（新 `scope_id`）并选中。  
- 修改当前**未开**人标记名 = 改名（仍禁重名），不是开票购方。  
- **签发**时才把当前人份额写入 allocation（OCC）并 `mode=person` 开票。

### 4.5 开票后

1. 当前人至少一行有效份额；NIF 规则同现工作台。  
2. 提交 allocation（已开人份额必须与库中一致，不得改）+ `POST .../issue`。  
3. 成功：该人 ✓；份额永久占用；**清空开票条**；选中下一未开人（顺序）；若无未开人且池空 → 清草稿。  
4. 人开完但池非空 → 草稿保留；可再建人继续挖池，或「不再处理未开部分」。

## 5. 状态机

```
[列表] → 进入工作台
[当前人编辑] 改标记名/份额（未提交）；开票条填购方
    → 切其他未开人：丢未提交；清空开票条
    → 点已开人：只读
    → 签发成功：✓；清空开票条；下一未开人
[全部未开开完且池空] 删草稿 → 回列表
```

### 5.1 并发（OCC）

分配写入仍 OCC；签发带 `allocation_revision`。已开人服务端锁定份额（防超开），**不是**跨票购方身份约束。

## 9. 非目标

- 回写 Farvoo；even/custom 金额分单；P0 改价删菜；自助客分单；多次同步冲突合并。

### 9.1 实现须挡

| 项 | 定法 |
|----|------|
| 超开 | 占用 ≤ 源行 |
| 已开份额 | 不可在后续 PUT 中被改掉（防超开）；UI 已开只读 + 签发只提交当前未开人变更 |
| 清草稿 | 人开完且池空 |
| 切人 | 不隐式保存 |

## 10. 验收（产品）

1. 顶上人条可点；已开 ✓ 且可点只读。  
2. 中间+开票同时只反映一人。  
3. 切未开人：未提交改动丢弃；开票条清空。  
4. 中间标记名 ≠ 票面购方；两者可不同。  
5. 无「添加用餐人」「保存分单」主按钮；姓名即建人/改标记；签发即提交。  
6. 云端 split 默认加载已知人，选中第一未开；开完顺序下一未开。  
7. 先开 A 再开 B；跨票购方无约束；A 菜不回池。  
8. 刷新后已提交分配仍在。  
9. 人开完池非空 → 草稿仍在。
